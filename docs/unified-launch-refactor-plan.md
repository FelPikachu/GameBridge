# GameBridge 统一启动架构整理计划

状态：**仅存档，尚未实施**
记录日期：2026-08-29

## 为什么要整理

当前四款米哈游游戏已经能够运行，但启动判断是在多次修复过程中逐步叠加的。不同游戏、区服和兼容层的特殊判断分散在多个位置，容易出现“修好一个路线，意外影响另一个路线”的情况。

这次整理不追求让所有游戏强行共用同一个兼容层。目标是：**用户操作统一、代码管理统一，但每款游戏继续使用已经验收成功的运行方式。**

## 用户看到的流程

用户仍然只需要：

1. 选择官服、B 服或国际服。
2. 根据需要选择普通启动、小黄鸭、DeckyFG/FSR 或组合模式。
3. 点击开始游戏。

不增加手动选择兼容层、Prefix 或启动参数的操作。

## 新的内部流程

```text
用户点击同一张 Steam 游戏卡片
        ↓
统一启动中心读取：游戏、区服、启动插件
        ↓
读取这条路线的“游戏说明卡”
        ↓
检查硬盘、游戏程序、渠道文件和兼容层
        ↓
选择固定执行器和独立运行环境
        ↓
最后套用小黄鸭或其他启动插件
        ↓
启动游戏并记录可追踪日志
```

## 游戏说明卡

说明卡只描述差异，不在各处重复编写判断代码。

| 游戏路线 | 固定启动要求 |
| --- | --- |
| 原神官服 / B 服 | `YuanShen.exe`、Steam 直接启动、DWProton、启动前自动切换渠道 |
| 原神国际服 | `GenshinImpact.exe`、GameBridge 原生入口、UMU、DWProton、国际服独立环境 |
| 绝区零官服 / B 服 | GameBridge 统一入口、UMU、DWProton、启动前自动切换渠道 |
| 绝区零国际服 | GameBridge 统一入口、UMU、DWProton、国际服独立环境 |
| 星穹铁道官服 / B 服 | GameBridge 统一入口、DWProton、启动前自动切换渠道 |
| 星穹铁道国际服 | GameBridge 统一入口、UMU、DWProton、国际服独立环境 |
| 崩坏3官服 / B 服 | GameBridge 统一入口、GE-Proton 11-5、启动前自动切换渠道 |
| 崩坏3国际服 | GameBridge 统一入口、Steam 官方 Proton Hotfix、国际服独立环境 |

兼容层缺失时只能自动准备指定兼容层或显示明确错误，不得偷偷换成另一种兼容层继续尝试。

## 三种固定执行器

统一启动中心只调用下面三类执行器：

1. **Steam 直接启动**：用于已经验收的国服 / B 服原神路线。
2. **GameBridge＋UMU**：用于适合 UMU 的游戏路线。
3. **GameBridge＋Steam Proton**：用于需要 Steam Proton 直接运行的特殊路线。

执行器负责真正启动；游戏说明卡负责告诉执行器使用哪个程序、兼容层和环境。两者不再混在一起。

## 小黄鸭和其他插件

启动插件必须在正确游戏路线确定以后再加入：

```text
正确的基础启动路线
        ＋
小黄鸭 / DeckyFG / 组合模式
        ↓
最终启动命令
```

关闭启动插件时，必须从当前游戏和当前区服的说明卡重新生成普通启动路线，不能恢复历史字符串或其他区服的参数。

已经锁定的国际服四款小黄鸭路线不得改变。DeckyFG/FSR 和组合模式需要先完成真机验收，才能加入同等级保护。

## 必须保护的内容

整理过程中不得改变：

- 四款游戏的 Steam App ID、封面、手柄布局和统一卡片。
- 官服、B 服、国际服现有的游戏程序选择。
- 已验收的兼容层版本和启动参数。
- 各国际服游戏相互独立的运行环境。
- 官服与 B 服之间的渠道文件切换和恢复能力。
- 外置硬盘未连接时的安全提示。
- 普通启动和已经验收的小黄鸭启动结果。

详细真机保护范围以 `docs/verified-baseline.md` 为准。

## 安全实施顺序

1. 先完成 DeckyFG/FSR 和组合模式的剩余真机验收并写入保护锁。
2. 把当前每条成功路线的最终程序、参数、兼容层和环境记录成测试样本。
3. 新建统一启动中心和说明卡，但暂时仍调用旧启动代码。
4. 自动比较整理前后的最终启动结果；不一致就停止。
5. 每次只迁移一款游戏的一个区服。
6. 每一步都运行完整回归保护锁。
7. 每款游戏迁移后重新进行大屏幕真机启动测试。
8. 全部通过以后再删除被确认不再使用的旧判断代码。

## 回退规则

- 旧启动路线在对应新路线通过自动检查和真机验收前不得删除。
- 每次修改只影响一条明确路线，失败时只回退这一条。
- 任何已验收功能失效，都必须停止整理，恢复最后通过的安装包。
- 不允许为了代码看起来整洁而接受功能退步。

## 完成标准

只有同时满足以下条件，才可以说统一启动架构整理完成：

- 用户操作没有变复杂。
- 所有已锁定路线重新通过真机验收。
- 启动插件恢复与切换不会破坏基础路线。
- 游戏差异集中在说明卡中，不再散落重复判断。
- 三种执行器职责清楚，没有游戏名称硬编码到无关模块。
- 完整保护锁、前端构建和 ZIP 打包检查全部通过。
